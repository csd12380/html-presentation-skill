# HTML 演示站制作技能

一个给 AI 编码助手用的技能包：把任意主题做成**高端网站级的 HTML 演示作品**——单文件、可全屏、图文动效三维兼备，而不是"PPT 转网页"。

作者：**taidi-chenside**

## 它解决什么问题

用 AI 做网页版 PPT，常见的失败长这样：

- 图片直接贴上去，像手工拼的，没有设计感
- 同一个建筑做出来四张图四个样子
- 生成图片时没定风格，图和页面各走各的配色
- 做完才发现字小得投屏看不见
- 界面上一堆"上一页/下一页"按钮，像播放器不像作品
- 打开第一页不翻页时，画面就是一张死图，只有切换才有动效
- 号称加了几十种动效，实际幅度小到肉眼几乎看不见（周期 48s、位移 1.5%，1 秒只走 0.6px）

这个技能把这些坑写成了硬性规则：逐页判断素材、生图前必须先写提示词、同一主体锁母图、图片必须融入页面、交付前逐页截图自检。

## 七段流程

```
0 环境探测  → 判定是否支持 AI 生图 + 盘点用户提供的素材
1 大纲      → 大纲.md（每页含"素材需求"字段）
⏸ 大纲确认  → 停下来给用户看，等他说"可以"才继续（硬卡点）
1.5 风格锁  → 视觉规范.md（配色/材质/光影/构图 + 明度错开）
2 素材      → 逐页判断来源：用户图 > 生图(先写提示词) > SVG
3 HTML      → 单文件 index.html，每页分配不同融入方式
4 动效三维  → 入场动画 + 环境态循环 + 交互 + 三维
5 自检      → 逐页截图 → 看图修问题 → 复检
6 交付      → 成品 + 中间产物清单
```

**大纲确认是唯一的人工卡点。** 大纲写完必须先停下来：把大纲正文贴给用户、问清页数/顺序/观点/风格要不要改，得到明确同意后才进入生图和写页面。

## 核心铁律

1. 大纲必须经用户确认才能往下做
2. 生图前必须先写提示词（风格锁段 + 内容段 + 一致性段）
3. 用户给了图 ≠ 素材齐了，仍要逐页判断是否缺图
4. 同一物体/产品多页出现时先定母图，后续只改机位和光线
5. 图片要"长"在页面里，不是"贴"上去（14 种融入手法）
6. 风格锁三原则：色系一致 + 明度错开 + 光影定向
7. 不显示翻页按钮，用键盘方向键 + 鼠标滚轮翻页
8. 交付前必须逐页截图自检，并用 `check.py` 验活动效，改到达标
9. 页面不切换时也必须**明显**在动：每页 3–4 个环境态循环 + 至少一个强可见主运动（光柱/粒子/光幕/波浪），周期 5–28s、位移 ≥3%，交付前 `check.py` 必须判「明显可见 ✅」

## 安装

把整个目录复制到技能目录即可（用户级，所有项目通用）：

```bash
# macOS / Linux
cp -r html-presentation-skill ~/.workbuddy/skills/

# Windows
xcopy html-presentation-skill %USERPROFILE%\.workbuddy\skills\html-presentation-skill\ /E /I
```

放到某个项目的 `.workbuddy/skills/` 下，则只在该项目生效。

## 成品示例

用它做过两个完整案例（成品在各自的项目目录里，不在本仓库）：

- **萨伏伊别墅**：先定母图再生成 10 张机位图，每页用不同的融入手法
- **广州塔**：11 页，6 张生成图 + 5 页内联 SVG，纯键盘 + 滚轮翻页

## 依赖

- Python 3（跑 `scripts/` 下的两个脚本）
- Playwright + 系统 Chrome（只用于自检截图，`check.py` 会自动装 playwright，浏览器复用本机 Chrome）
- 生图能力可选：平台没有生图工具时，技能会退回"用户图 + 内联 SVG"路线

自用为主，随便改。技能方法论来自对公开教程的学习与实战迭代。
