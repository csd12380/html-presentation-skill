# 大纲规范

大纲是整套演示的"图纸"，是后续所有环节的依据。写不好大纲，后面每一步都会乱。

## 产出格式

生成 `大纲.md`，包含两部分：

### 第一部分：全局设定

```markdown
# <主题> · 演示大纲

- 主题：
- 目标读者：
- 页数：N 页
- 整体风格：（米白杂志 / 深蓝科技 / 手绘 / 极简白，见视觉规范.md）
```

### 第二部分：逐页表

用 Markdown 表格，每页一行，字段如下：

| 字段 | 说明 | 要求 |
|---|---|---|
| 页序 | 01 / 02 / 03... | 从封面开始 |
| 页面类型 | 封面 / 目录 / 内容 / 交互 / 结尾 | 明确这一页的角色 |
| 核心观点 | 这一页只讲什么 | **一页只讲一个观点** |
| 画面内容 | 这一页画面上要有什么 | 具体到"图/图形/数据/文字"各是什么 |
| 文字 | 这页要放的文字 | **≤60 字**，投影环境超了看不见 |
| 素材需求 | 用户图 / 待生图 / 待SVG / 视频 / 无 | 供第 2 段判断用，先按内容类型初判 |

## 大纲确认（硬卡点，不可跳过）

`大纲.md` 写完，这一轮就结束，先把大纲交给用户看。**不许接着写视觉规范、不许开始生图。**

### 交出去时必做三件事

1. **把大纲正文贴在对话里。** 全局设定 + 逐页表格全贴，不要只说"已生成 大纲.md，请查看"，用户不一定去开文件。
2. **点出要用户拍板的几处。** 挑真正需要他决定的，不要把所有字段都问一遍：
   - 页数：N 页会不会太多 / 太少？哪一页可以合并、哪一页要拆开？
   - 顺序：讲下来的逻辑顺不顺？有没有该往前挪的页？
   - 观点：每页那句"核心观点"有没有说错的、说浅的、漏讲的重点？
   - 风格：给出 2–3 个候选（如米白杂志 / 深蓝科技 / 极简白），每个附一句差异，让他挑一个。
3. **明确说出下一步。** 一句话讲清："你确认后我就开始定风格、找素材、写页面。"

### 用户回话后的处理

| 用户说 | 怎么做 |
|---|---|
| "可以 / 没问题 / 继续" | 记下确认结论，进入 1.5 风格锁 |
| "第 X 页改成……" "加一页……" "删掉……" | 改 `大纲.md`，把**改动的那几行**贴出来复述一遍，再问一次"这样对吗"，得到确认才继续 |
| 提了内容层面的补充资料 | 先并入大纲（可能牵动页数和观点），改完再确认一轮 |
| 没回话或只回了别的事 | 就停在这里等，不要自己开工 |

改动大的（页数变化超过 2 页、顺序重排、风格换了），必须整份重新贴一遍再确认，不能只贴改动行。

### 禁止

- 禁止"大纲我写好了，我继续做后面的了"这种一句话交差。
- 禁止自我批准："大纲合理，我直接开工"。
- 禁止把大纲和成品一起交，那等于没确认。

## 三条硬规则

1. **一页一个观点。** 一页塞两个观点，后面视觉设计必然冲突，这是原视频案例反复强调的。
2. **文字 ≤60 字。** 每页文字是"点睛"，不是"说明书"；详细内容让图、图形、动效去讲。
3. **"画面内容"要具体。** 不能写"放一张图"，要写"放一张 XXX 的低角度外观图 / 一张 XXX 的结构示意 / 一组 XXX 的数据对比"。

## 素材需求字段的初判规则

写大纲时，先按"内容类型"给素材需求打个初判，第 2 段再结合用户素材和生图能力二次确认：

| 内容类型 | 初判素材需求 |
|---|---|
| 氛围 / 外观 / 场景 / 实景 | 待生图（或用户图） |
| 讲逻辑 / 关系 / 结构 / 流程 | 待SVG（内联示意图） |
| 数据对比 / 数字结论 | 待SVG 或纯排版 |
| 金句 / 结论 / 收尾 | 无 |
| 封面 / 结尾氛围 | 待生图（或视频/用户图） |
